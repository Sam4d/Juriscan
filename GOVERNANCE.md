# Governance

The repository owner maintains release and licensing decisions. Technical reviewers own reproducibility, schemas, tests and security boundaries. Legal review is a separate responsibility requiring jurisdiction/subject-matter competence and a recorded scope, source version, date, conflict disclosure and review deadline. No legal reviewer is appointed or implied by this repository.

No one may promote research candidates to active legal conclusions merely by editing a status field. The current implementation deliberately has no active-law schema or enforcement path. Such an addition needs reviewed design, source governance and tested applicability. Technical confidence and legal certainty remain separate.

Breaking CLI/MCP/schema changes require release notes and version changes. Alpha interfaces may change. Document deprecations and migration advice. Publish only observed validation results; list unrun and blocked checks explicitly. Contribution review must preserve the distinction between a public source release and production/legal certification.
